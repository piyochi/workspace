# 個人の作業ルール（Codex 向け・全プロジェクト共通）

## コメントは書かない（Claude が後で書く）

このユーザーの環境では、コードは Codex、ソースのコメントは Claude が書く分担にしている。

- メソッドコメント・YARD（`@param` / `@return` / `@raise`）・JSDoc（`@param` / `@returns`）・定数や処理の説明コメントは**書かない**
  - プロジェクトの規約に「メソッドには必ずコメント」とあっても、それは完成形の規約。コメントは Claude が実装後に `ct-method-comments` で書き足し、Codex が実コードと照合する
- **`@tag` は付ける**（`# @tag 機能名` / `// @tag 機能名`）。コミット前に `bin/tracecheck untagged --gate` が付け忘れを止めるため。書き方は各プロジェクトの `.claude/rules/source-tags.md` に従う
- RuboCop の抑制コメント（`# rubocop:disable ...`）など、ツールに必要な注記は書いてよい
- 定数の値・正規表現・上限値・分岐の理由など「なぜこうしたか」は、コードに書かず**報告ファイルに書く**（Claude がコメントにするときの材料になる）
- 依頼文で明示的にコメントを書くよう指示された場合は、その指示に従う

## テスト・lint は変更したファイルの分だけ

- ローカルで回すテスト（RSpec / Vitest）と lint は、**変更・追加したファイルに対応するものだけ**。全体テスト・広い回帰は CI に任せる
- 依頼文でテストの範囲を指定されたら、それに従う
- 実行したコマンドと件数（examples / failures など）を報告ファイルに書く。Claude はこの結果をそのまま使い、同じテストを回し直さない

## 文体

- 和語（「〜を取り直す」「突き合わせる」「〜に寄せる」「見張る」など）を避け、熟語とカタカナ語で説明する
  - 例: 取り直す → 再取得 / 突き合わせる → 照合 / 裏取り → 検証 / 見張る → 監視 / 区切り → 単位・タイミング
- コード識別子・コマンド名はそのまま
