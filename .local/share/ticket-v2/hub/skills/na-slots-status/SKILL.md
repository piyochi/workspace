# na-slots-status（hub 専用・Claude が実行する）

/na-watch（固定したチケットの流れ）・/na-list（画面の要約。ポップアップ）と違い、会話の中に表で答え、次の一手まで提案する。
**読むだけ。枠に何も送らない・サーバーの使用中を外さない・スキルを頼まない**（提案はコマンドの形で示し、ユーザーが打つ）。

## 手順

1. `python3 -B ~/.local/share/ticket-v2/hub/bin/hub_slots.py $ARGUMENTS` を実行する（材料。1〜2秒）
2. 次の形で答える。材料に無いことは書かない（推測は「〜と見られます」）
   - 1行目: 取得時刻・開発用サーバー（使用中・待ち）
   - **あなたの番**（先に出す）: 画面の最後の段落が質問（？・「〜ますか」「〜してよいですか」）・「確認待ち（許可）」・ct-fix-loop の `止まっている`・入力欄に未送信の文がある枠。1枠1行で「[枠] #番号: 何を聞かれているか → 答え方・打つコマンドの例」
   - **全部の枠の表**: | 枠 | チケット | 状態 | 何を待っているか | 最後の動き | 次に止まる所 |
     - 状態: 処理中・入力待ち・確認待ち・未起動・空き（新しい会話・チケットなし）
     - 何を待っているか: あなたの答え／Codex の返事（相方が処理中・fix-loop の waiting=codex）／開発用サーバーの順番（順番待ち N 番目）／サブエージェント／なし
     - 「最後の動き」が 30 分以上前で入力待ちなら「止まっている見込み」と書く
   - **気になる点**（あれば3件まで）: 例 使用中なのにサーバーを使っていない・同じチケットが2枠・hub の依頼の失敗（⛔）・会話が 400k 以上
   - **次の一手の提案**（あれば）: `/na-next 番号`・`/na-go 番号 fix`・`/na-to 枠 …`・`/na-server-status release 番号` の形で示す
3. 表は短く。画面の文をそのまま長く貼らない（1セル 40 字目安）
